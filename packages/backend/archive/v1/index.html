Auth

Authentication and OTP flows

Verify a Firebase phone-auth ID token

Verifies a Firebase ID token obtained after the client confirms the OTP via the Firebase Phone Auth SDK (OTP delivery and confirmation happen entirely client-side). On success, returns a JWT token to be used for authenticated requests.

Request Body schema: application/json
required
idToken
required
string

Firebase ID token obtained after the client confirms the OTP via the Firebase Phone Auth SDK. The backend verifies this token's signature and validity via the Firebase Admin SDK and trusts its phone-number claim.

Responses

Goals

Saving goals management

List saving goals

Returns all saving goals for the authenticated user, ordered by creation date descending. Optionally filter by status.

Authorizations:
bearerAuth
query Parameters
filter
string
Example: filter=status eq ACTIVE and currency eq INR

Filter expression supporting comparison and logical operators.

Grammar

expr       = term ( ("and" | "or") term )*
term       = field operator value | "(" expr ")"
operator   = "eq" | "neq"
field      = "status" | "currency"
value      = bare word (no quotes)

Operator precedence follows standard rules — and binds tighter than or. Use parentheses to override.

Supported fields

Field Type Allowed values
status enum ACTIVE, COMPLETED, CANCELLED
currency string ISO 4217 code, e.g. INR, USD

Examples

  • status eq ACTIVE
  • status neq CANCELLED
  • status eq ACTIVE and currency eq INR
  • status eq ACTIVE or status eq COMPLETED
  • (status eq ACTIVE or status eq COMPLETED) and currency eq INR
token
string

Opaque pagination cursor returned in paging.nextToken or paging.previousToken from a previous response. Omit to fetch the first page.

size
integer [ 1 .. 100 ]
Default: 20

Number of goals per page. Capped at 100.

Reorder saving goals

Replaces the display order of all saving goals for the authenticated user in a single atomic operation. The request must include every goal owned by the user — partial lists are rejected with 400.

Constraints

  • orderings must contain exactly one entry per goal owned by the user.
  • order values within the list must be unique non-negative integers.
  • Goals belonging to other users are ignored if accidentally included and will not cause an error; only the caller's goals are updated.
Authorizations:
bearerAuth
Request Body schema: application/json
required
required
Array of objects non-empty

Complete list of goal-to-order mappings for the authenticated user. Every goal owned by the user must be included; omitting a goal is a validation error. Order values must be unique non-negative integers.

filter
string
Example: filter=type eq DEBIT and createdAt gte 2026-06-01T00:00:00Z and createdAt lte 2026-06-30T23:59:59Z

Filter expression supporting comparison and logical operators.

Grammar

expr       = term ( ("and" | "or") term )*
term       = field operator value | "(" expr ")"
operator   = "eq" | "neq" | "gt" | "gte" | "lt" | "lte" | "co"
field      = "type" | "createdAt" | "accountId" | "budgetId" | "title"
value      = bare word | "quoted string"

Operator precedence follows standard rules — and binds tighter than or. Use parentheses to override. Multi-word values must be wrapped in double quotes.

Supported fields

Field Type Operators Allowed values / format
type enum eq, neq CREDIT, DEBIT
createdAt date-time gt, gte, lt, lte ISO 8601 UTC, e.g. 2026-06-01T00:00:00Z
accountId UUID eq Valid UUID
budgetId UUID eq Valid UUID
title string co Any string (case-insensitive partial match)

Examples

  • type eq DEBIT
  • type neq CREDIT
  • createdAt gte 2026-06-01T00:00:00Z
  • title co grocery
  • title co "grocery run"
  • type eq DEBIT and title co grocery
  • type eq DEBIT and createdAt gte 2026-06-01T00:00:00Z
  • type eq DEBIT and createdAt gte 2026-06-01T00:00:00Z and createdAt lte 2026-06-30T23:59:59Z

Enable or disable a recurring transaction rule

Updates a recurring transaction rule. enabled is the only field that can be changed — every other property of the rule is fixed at creation time (set when the originating transaction was created with recurringRule). Setting enabled to false stops future reminders; setting it back to true resumes them. Returns 404 if the rule does not exist or does not belong to the authenticated user.

Scheduler

On-demand goal allocation schedule execution

Trigger pending goal allocation schedules

Immediately checks for any goal allocation schedules that are due for the authenticated user and executes them. Useful on app load to process overdue allocations without waiting for the next background poll (which runs every 60 seconds).

The operation is idempotent — if no schedules are due, it completes without any side effects. Each due schedule creates an allocation job that transfers the fixed amount from the user's unallocated balance into the target goal.

Notifications

Push notification device token registration

Register a device push token

Registers (or refreshes) an Expo push token for the authenticated user's device, so the backend can send push notifications to it. Idempotent — calling this again with the same token for the same user simply refreshes it. If the token was previously registered to a different user (e.g. app reinstalled or a different account signed in on the same device), that prior registration is deactivated.
